受控 变更

三类远端写全部 preview → confirm；超时进 uncertain，读回对账，不盲重试。

合并资格门 七条 fail-closed

✓ cr_open

平台 PR 状态 opened

✓ not_draft

非 draft / WIP

✓ head_match

远端 head 与 expected_remote_head 一致（陈旧拒绝）

✓ mergeable

merge_status 已知且可合并（unknown/checking/conflict = 阻断）

✓ review_done

当前 head 审查完成且 verdict 已知

✓ no_blocking_findings

无未处理 critical / high 发现

✓ ci_pass

CI 通过（Statuses + Check Runs 双面取最坏；无 CI = 阻断）

三类受控写

写门绑定
修复推送审批票 + await_confirmtask_id + expected_remote_head
合并资格门七条op_id + expected_remote_head
评论陈旧 head 复核 + 幂等原位更新task_id 锚点

审批票 （critical / high）

具名批准

按 (PR, fp, head) 建票；@argus fix 与推送环均要求 approved 才放行——缺票 = 未批准。

陈旧失效

新 head 重建票，旧 pending → stale；陈旧证据不可放行。

CAS 裁决

仅 pending 可裁决；二次裁决幂等拒绝——并发双批不会双写。

非递增角色

maintainer 可裁定不可管理；admin 可管理不可裁定（防越权合码）。

预览 → 确认

  POST /merges/preview     →  op_id + expected_remote_head（资格门全绿才建候选）
  POST /merges/confirm     →  绑定 head 三方一致 + 副作用闸 at-most-once + MergeCR
        │ 超时 / 断连
        ▼
  uncertain  →  POST /merges/reconcile 读回对账（平台实际状态幂等定案）
