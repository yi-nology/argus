为什么这样设计

需求不是代码

从 PR / issue 改写验收清单，逐条判定 implemented / partial / missing。缺证据的判定降级为 unverifiable，不许"看起来做了"。

裁决不靠模型心情

R5 真值表按序短路，纯 Go 代码。注入攻击的极限只是 COMMENT——永不白给 APPROVE。

写远端是特权

评论、推送、合并三类写全部两阶段确认，绑定 expected_remote_head。超时进 uncertain，读回对账，不盲重试。
