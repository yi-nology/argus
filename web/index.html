需求复核 R1–R5

从 PR/issue 改写验收清单，逐条 implemented / partial / missing，证据必须 file:line，无证据降级 unverifiable。

多专家并发审查

builtin / CLI 编码 agent / 远端 agent 插件 fan-out；互盲独立或黑板共识；指纹去重、冲突取高、best-of-N 复现投票。

⚖️

确定性裁决

真值表按序短路（R5.1–R5.5）零 LLM：需求未完成一票否决，注入攻击极限只是 COMMENT，永不白给 APPROVE。

🔐

修复审批票

critical/high 按 (PR, fp, head) 建具名票；缺票 = 未批准（fail-closed）；新 head 旧票 stale。

🚧

合并资格门

七条 fail-closed：开放 / 非 draft / head 一致 / mergeable 已知 / 审查完成 / 无高危 / CI 通过。

🤖

AI 工作台

审查 管线

一次审查的旅程：事件 → 多专家 → 确定性裁决 → 双层回帖。

  PR opened / push ─┬─ webhook（签名校验、delivery 幂等）
                    ├─ poller（NAT/VPN 兜底）
                    ├─ POST /tasks（Bearer）
                    └─ MCP review_pr
                            │
                            ▼
              R1 需求解析 → R2 变更理解 → R3 完成度判定（ReAct+工具）
              → R4 并发委派插件（builtin / cli / acpx / remote）
              → R5 真值表裁决  APPROVE / COMMENT / REQUEST_CHANGES
                            │
                            ▼
              行内评论 + 总结报告（原地更新，不刷屏）
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
        修复审批票      受控推送       合并资格门
        （具名批准）   （绑 head）    （七条 fail-closed）

受控 变更

三类远端写全部 preview → confirm；超时进 uncertain，读回对账，不盲重试。

✓ cr_open

平台 PR 状态 opened

✓ head_match

远端 head 与 expected_remote_head 一致（陈旧拒绝）

✓ review_done

当前 head 审查完成且 verdict 已知

✓ no_blocking

无未处理 critical / high 发现

✓ ci_pass

CI 通过（无 CI 或读取失败 = 阻断，fail-closed）
