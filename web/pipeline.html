Review Pipeline

五步审查，结论可复现

R1–R5 是固定编排：需求解析 → 变更理解 → 完成度取证 → 多专家互查 → 确定性裁决。同样的输入给出同样的结论。

各阶段做什么

R1 需求解析

从 PR 描述 / 关联 issue 改写验收清单 AC-1..N。分支名含 #N 也能自动关联 issue。

R2 变更理解

解析 diff、影响面（调用图 / 受影响包 / 历史共变），供后续阶段引用。

R3 完成度判定

带工具的 ReAct agent 逐条核对 AC，每条判定必须带 file:line 证据；无证据强制降级 unverifiable。

R4 多专家并发

builtin / CLI 编码 agent / 远端 agent fan-out。互盲独立或黑板共识；指纹去重、冲突取高严重度。

R5 确定性裁决

真值表按序短路，零 LLM。产出 APPROVE / COMMENT / REQUEST_CHANGES 与规则号。

裁决真值表

规则条件结论
R5.1missing + partial > 0REQUEST_CHANGES — 需求未完成，一票否决
R5.2存在 high findingREQUEST_CHANGES
R5.3unverifiable / 需求模糊 / scope creepCOMMENT — 人工确认
R5.4存在 medium / low findingCOMMENT
R5.5其余APPROVE

多专家编队

互盲独立

成员并发盲审，分歧由 Merger 标注"另一专家未复现"。保留分歧信号，适合探索型审查。

黑板共识

成员按轮互看共享黑板，只补他人未覆盖的新问题；一整轮无人补充即收敛。适合高危变更。
