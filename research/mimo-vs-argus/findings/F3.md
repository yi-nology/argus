# F3: Why MiMo-class agents feel smart and usable

## Findings

### [1] MiMo Code frames long-horizon agent quality as three orthogonal runtime bottlenecks — per-turn compute, within-session state, and cross-session experience distillation — rather than model IQ alone.
- quote: "同 session 的单轮决策质量主要受限于计算量，同 session 的多轮任务连续性主要受限于状态管理，跨 session 的任务改进主要受限于经验的提炼机制。而这三种时间尺度，恰好分别对应：计算、记忆、进化"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [2] MiMo explicitly rejects pure-compaction memory and replaces it with an explicit store–retrieve mechanism, because high-utilization windows degrade extraction quality (lost-in-the-middle) and leave no room for the writer to think.
- quote: "我们需要的不是更好的压缩，而是一套显式的存储-检索机制，决定什么信息在什么时候被写入持久结构、什么时候被召回。……因此 checkpoint 在远低于上限处触发——大致在已配置预算的 20%、45%、70%。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [3] MiMo Code separates memory writers from the main agent: the working model never maintains its own structured memory; a dedicated checkpoint-writer subagent extracts 11-field state concurrently, and only a free-form notes.md scratchpad is writable by the main agent.
- quote: "主 Agent 不维护自己的记忆。提取被完全移出主循环，由运行时触发，由一个独立的 writer subagent 完成——它不与主 Agent 共享注意力或 token 预算。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [4] Rebuild injection is a layered, budgeted prompt (task list → session checkpoint → verbatim recent user messages → project/global memory → notes → path index → tail reminder), capped ~65K tokens, so logical sessions can chain across unbounded physical cycles without re-deriving the goal.
- quote: "当运行时执行 rebuild 时，它将持久化的文件组装为一个分层的 prompt 注入新窗口，每一段有独立的 token 上限。……即使每段都顶满上限，注入总量也控制在约 65K token 以内"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [5] Test-time compute is split into two orthogonal feedback loops: Max Mode (N≈5 parallel candidates + judge, +10–20% on SWE-Bench Pro at ~4–5× tokens) and Goal (independent stop-condition judge that blocks optimistic stops; false-block > false-release, loop risk <0.5%).
- quote: "Max Mode 解决的是「做对」，Goal 解决的是「做完」。……在 SWE-Bench Pro 上，Max Mode 相比单次采样提升 10-20%，代价是约 4～5 倍的 token 消耗。……整体死循环概率小于 0.5%"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [6] Deterministic Dynamic Workflows move orchestration out of natural language into sandboxed JavaScript (`agent()`, `parallel()`, resumable logs) because prompt-encoded process is forgettable under compaction and non-verifiable across runs.
- quote: "编排逻辑以自然语言存在，而自然语言是模糊的、可遗忘的、不可验证的。Dynamic Workflow 把编排逻辑从 prompt 变成代码。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [7] Cross-session "evolution" is productized as inspectable Markdown project memory + two scheduled self-maintenance agents: Dream (7-day memory consolidation) and Distill (30-day workflow-to-skill packaging), chosen over opaque vector DBs for auditability.
- quote: "选择文件而非纯向量数据库，核心原因是可审查性……Dream 每 7 天自动触发……Distill 每 30 天自动触发……识别反复出现的工作模式，将其固化为可复用的 skill"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [8] Model-side intelligence for coding is engineered via hybrid SWA/GA attention (6:1, window 128, ~7× KV reduction) + 3-layer MTP + 1M context + large-scale agentic RL on 100k+ GitHub-issue tasks; MiMo-V2.5-Pro is marketed for trajectories spanning thousands of tool calls with long-horizon coherence.
- quote: "MiMo-V2.5-Pro is our most capable model to date, designed for the most demanding agentic, complex software engineering, and long-horizon tasks. It sustains complex trajectories spanning thousands of tool calls with strong instruction following and coherence over a 1M-token context window."
- url: https://huggingface.co/XiaomiMiMo/MiMo-V2.5-Pro
- source_type: primary
- published: 2026-07-09 (HF card update)
- confidence: high

### [9] Multi-Teacher On-Policy Distillation (MOPD) integrates domain RL teachers into one student on the student's own rollouts with dense token-level reverse-KL, avoiding exposure bias, reward-hacking, and Mix-RL see-saw interference — this is the mechanism behind "one model that feels good at many agent tasks."
- quote: "MOPD also enables parallel, independent development of domain teachers, removing the cross-domain coupling typical of multi-domain post-training. MOPD has been deployed in the post-training of MiMo-V2-Flash"
- url: https://arxiv.org/html/2606.30406
- source_type: primary
- published: 2026-06-30
- confidence: high

### [10] General best practice: multi-agent systems feel smart mainly because they scale tokens and isolate context (orchestrator–worker, plan-to-memory, subagent compression), not because multi-agent is always better — coding has fewer truly parallel units than research.
- quote: "Multi-agent systems work mainly because they help spend enough tokens to solve the problem. … token usage by itself explains 80% of the variance … most coding tasks involve fewer truly parallelizable tasks than research"
- url: https://www.anthropic.com/engineering/built-multi-agent-research-system
- source_type: primary
- published: 2025-06-13
- confidence: high

### [11] General best practice: perceived usability is dominated by context engineering + verification loops — plan mode separates explore/plan/code, CLAUDE.md keeps durable rules out of conversation, subagents keep research out of main context, checkpoints/rewind make failure recoverable, and independent judges/goal conditions prevent optimistic stops.
- quote: "Most best practices are based on one constraint: Claude's context window fills up fast, and performance degrades as it fills. … Give Claude a way to verify its work … Explore first, then plan, then code"
- url: https://code.claude.com/docs/en/best-practices
- source_type: primary
- published: unknown (current docs as of 2026-09)
- confidence: high

### [12] Product UX pattern shared by MiMoCode/Claude Code: progressive disclosure (on-demand skills/subagents), dual permission models (read-only plan vs full build), mode lock after first message to stabilize tool-call reliability, and cost-aware routing/cache claims make autonomous long runs feel controllable rather than magical.
- quote: "After the first message the mode locks: Build and Plan can still switch between each other, but Compose is isolated once entered — keeping the skill/tool set fixed from session start significantly improves tool-call reliability."
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: 2026-09-17 (repo snapshot)
- confidence: high
