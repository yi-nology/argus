# F2: MiMoCode / MiMo Desktop agent product

## Findings

### [1] MiMoCode is Xiaomi's open-source terminal-native coding agent (MIT), built as an OpenCode fork under the brand line "Where Models and Agents Co-Evolve."
- quote: "MiMoCode is a terminal-native AI coding assistant. It can read and write code, run commands, manage Git, and use a persistent memory system to keep a deep understanding of your project across sessions while continuously improving itself."
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: unknown (repo updated Sep 17, 2026)
- confidence: high

### [2] Public architecture philosophy is explicit: three themes — computation (test-time compute), memory (state continuity), evolution (cross-session improvement) — motivated by long-horizon failure modes of stateless LLM loops.
- quote: "我们观察到，在不同时间尺度上构成最突出的瓶颈分别是：同 session 的单轮决策质量主要受限于**计算量**，同 session 的多轮任务连续性主要受限于**状态管理**，跨 session 的任务改进主要受限于**经验的提炼机制**。而这三种时间尺度，恰好分别对应：**计算、记忆、进化**"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [3] Runtime vs model split is documented: the LLM is stateless; continuity is provided by the harness — checkpoint writer subagents, rebuild from persisted files, and single-writer memory paths.
- quote: "模型本身是无状态的——每次调用都从空白开始，所有连续性由运行时提供。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [4] Memory is a four-layer system (session checkpoint.md → project MEMORY.md → global prefs → SQLite history), with the main agent read-only on structured files except notes.md; checkpoints are written by a separate writer subagent at ~20%/45%/70% budget, not at context exhaustion.
- quote: "主 Agent 不维护自己的记忆。提取被完全移出主循环，由运行时触发，由一个独立的 writer subagent 完成——它不与主 Agent 共享注意力或 token 预算。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [5] Rebuild injection order and budget are public: task list → session checkpoint → verbatim recent user messages → project/global memory → notes → path index → tail reminder, capped around ~65K tokens so a logical session can chain unbounded physical windows ("cycles").
- quote: "即使每段都顶满上限，注入总量也控制在约 65K token 以内——在任何合理窗口的工作预算范围内。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [6] Product README and docs define three primary agent modes — build (full tools), plan (read-only; write/edit/bash disabled), compose (skill-orchestrated) — plus general/explore subagents; mode locks after the first message and Compose is isolated once entered to stabilize tool-call reliability.
- quote: "build Default. Full tool permissions for development / plan Read-only analysis mode for code exploration and solution design / compose Orchestration mode for specs-driven development and skill-driven workflows"
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: unknown (repo updated Sep 17, 2026)
- confidence: high

### [7] Subagent orchestration + stop-condition control are first-class: primary agents spawn parallel/background subagents with lifecycle/cancel; `/goal` uses an independent judge model to prevent premature "optimistic stops"; experimental Max Mode parallel-samples N≈5 candidates and judge-selects one (claimed +10–20% on SWE-Bench Pro at ~4–5× token cost).
- quote: "When the agent tries to stop, an independent judge model evaluates the conversation to decide whether the condition is truly satisfied — preventing premature \"optimistic stops\" during autonomous work."
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: unknown (repo updated Sep 17, 2026)
- confidence: high

### [8] Dynamic Workflows move orchestration out of prompts into deterministic sandboxed JavaScript (agent()/parallel()/pipeline(), resumable logs, worktree-parallel compose pipeline); four built-ins ship: compose, deep-research, fact-check, research-experiment.
- quote: "Workflows are deterministic JavaScript scripts that orchestrate multiple agents in a sandboxed runtime. Unlike agent conversations, workflows encode fixed phase sequences with bounded retries and automatic parallelization — fire-and-forget execution with no user interaction required."
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: unknown (repo updated Sep 17, 2026)
- confidence: high

### [9] Skills + self-evolution: builtin skills are discovered by exact name/alias/BM25 and auto-loaded; `/dream` (~7d) consolidates traces into project memory; `/distill` (~30d) packages repeated workflows into skills/commands/agents; public skill install also exists outside the CLI via XiaomiMiMo/MiMo-Skills (TTS skill for multi-agent hosts).
- quote: "Dream 每 7 天自动触发… Distill 每 30 天自动触发… 识别反复出现的工作模式，将其固化为可复用的 skill、CLI 命令、自定义 Agent 或 SOP 文档等。"
- url: https://mimo.xiaomi.com/zh/blog/mimo-code-long-horizon
- source_type: primary
- published: 2026-06-10
- confidence: high

### [10] Context-management UX is productized: automatic checkpoints, context reconstruction from memory/tasks/recent messages, budgeted injection, and model-scoped `/context-limit` / `compaction.max_context` (cost/quality motivated); marketing on mimo.xiaomi.com/coder frames this as "无限上下文" plus "自进化系统."
- quote: "Intelligent Context Management — Automatic checkpoints… Context reconstruction… Budgeted injection… Adjustable compaction point — /context-limit (or compaction.max_context) makes a model compact earlier than its own window, per model"
- url: https://github.com/XiaomiMiMo/MiMo-Code
- source_type: primary
- published: unknown (repo updated Sep 17, 2026)
- confidence: high

### [11] Public config surface (JSON Schema at mimo.xiaomi.com/mimocode/config.json) encodes agent/mode overrides, permissions (read/edit/bash/actor/skill/external_directory ask|allow|deny), MCP, skills.paths/urls, compose.docs, model_groups (ultra/standard/lite), small_model/vision_model, and experimental.maxMode — i.e. extensibility is schema-driven, not only prompt-driven.
- quote: "\"skills\": { \"description\": \"Additional skill folder paths\" … \"urls\": { \"description\": \"URLs to fetch skills from\" … } }"
- url: https://mimo.xiaomi.com/mimocode/config.json
- source_type: primary
- published: unknown
- confidence: high

- quote: "The desktop app is powered by **MiMo Code as its core engine**, bringing its terminal-native intelligence to desktop workflows."

- quote: "当执行步数在 200 步以内时，两者胜率接近 50%；当步数超过 200（包含多轮用户交互）后，MiMo Code 胜率升至 65% 以上。"
