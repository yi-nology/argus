> （机械裁剪丢掉关键结论时），按本手册落地，提示词与护栏模板直接抄。

对标：ZCode `core/src/compact/prompt.ts` + `turn-loop-state.ts`（rapid refill 熔断）。

## 一、压缩提示词三明治（模板）

压缩请求的提示词必须「首尾双硬约束」夹住正文——压缩轮通常复用带工具的模型，
模型在压缩轮幻觉调工具会浪费唯一一轮、甚至污染状态：

```
【前置硬约束】
本轮是上下文压缩：禁止调用任何工具。任何工具调用都会被拒绝并浪费本轮。
只输出文本。

【压缩正文（两段式）】
先在 <analysis> 中自查：当前任务的原始诉求是什么、已执行了哪些步骤、
哪些结论已坐实、哪些还是假设。然后在 <summary> 中按以下固定小节输出：
1. 原始诉求：用户的评审目标/约束（逐条保留，禁止改写措辞）
2. 安全红线：不得改代码、不得泄密、评审范围边界（逐字保留，禁止转述）
3. 已执行工具与结论：每条一行（工具名 + 关键参数 + 结论）
4. 已发现问题清单：file:line + 一句话（评审的主产出，逐条保留）
5. 当前假设与未验证疑点：明确标注「未验证」
6. 下一步：剩余待核查项

【尾部硬约束（重复一次）】
再次强调：禁止调用任何工具。只输出 <summary> 内容。
```

三条铁律（ZCode 实证）：
- **原始诉求逐条保留**（All user messages verbatim）——压缩丢诉求 = 后续全偏；
- **安全约束逐字保留**（security-relevant instructions MUST be preserved verbatim）
  ——评审红线被转述稀释是真实事故源；
- **摘要后接续提示**带「直接继续，不要复述摘要、不要道歉」（argus 的
  ContinueModel 续写指令同款纪律）。

## 二、压缩结果 + 读态重建（可选增强）

纯摘要对评审的保真度低于「摘要 + 最近读过文件的原文重建」：评审结论依赖
精确代码行。若做，重建参数照抄 ZCode：最近 ≤5 个文件、单文件 ≤5k token、
总量 ≤50k，超预算降级为一行「X 曾被读取，需要时重新调 get_file」。
排除项：`.git/`、已在保留段的文件（防重复）。

## 三、rapid-refill 熔断（启用压缩的前置条件，必做）

压缩后若 **少于 3 个工具轮** 再次逼近窗口上限（rapid refill），说明上下文
增长速度 > 压缩收益（典型：模型反复拉取大文件）。连续 3 次 rapid refill
直接终止任务（failed + 明确 fail_reason），**绝不进入 压缩→填充→压缩 无限环**
——那是 token 无底洞。argus 落地位：ctxfit 的 OnFit 事件里数
`FitMicro/FitTruncated` 的间隔轮次。

## 四、触发判定

- 判定用 **provider 真实 usage**（argus 已有：ctxfit 校准寄存器 +
  UsageHandler 回灌，v3.33.0），估算只做 fallback；
- 阈值 = 窗口 − 输出预留 − buffer，与 oagentkit fitInput 口径一致；
- 压缩轮本身也走 FitModel（压缩输入同样可能超窗）。
