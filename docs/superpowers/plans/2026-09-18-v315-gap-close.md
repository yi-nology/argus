# v3.15.0 主流差距收口批次 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地主流差距调研的 P0 三项（仓库级配置面、SAST 确定性扫描、AST 符号上下文）、P1 三项（describe/testgen 命令、评测北极星）、P2-7（MCP 副驾服务端底座）。

**Architecture:** 全部特性复用既有分层：仓库配置沿 `.reviewagents.yaml` → `plugin.ParseRepoConfig` → workflow/runner 消费；SAST 走 OCR delegate 同款"确定性前置"范式（不经 LLM，产出直接进 Merger outcomes）；AST 用 go/parser 纯 Go 实现（构建是 CGO_ENABLED=0，禁 cgo tree-sitter）进 R3/R4 工具表；describe/testgen 走评论轻量路径（与 Q&A 同款：不建 task、节流、幂等）；评测在既有 golden harness 上扩 clean/边界夹具与 FP 口径；MCP 新增三工具走既有 Core/可选接口模式。

**Tech Stack:** Go 1.x（stdlib go/parser、go/scanner）、gitleaks/semgrep 外部二进制（默认关）、mcp-go、yaml.v3。

**Spec:** 调研报告（会话 2026-09-18「调研和主流项目差距」）+ 用户拍板「P0 P1 P2-7」。

## Global Constraints

- 编译门禁 `CGO_ENABLED=0`（Makefile build）：禁止引入 cgo 依赖（tree-sitter 出局）。
- 红线不动：路由/裁决/合并不走 LLM；持久抑制只来自人工；锁定插件（lockRepoConfig）仓库配置关不掉；仓库配置只从默认分支读；`review.extra_instructions` 不能改变插件角色/输出格式/纪律（沿 guidelinesPrompt 既有声明）。
- 仓库配置（.reviewagents.yaml）按敌对输入对待：解析失败降级为无配置 + 告警，列表长度/文本长度收紧。
- 版本 v3.15.0；提交信息用仓库既有 conventional 中文风格；**严禁 `git add -A`**（并行会话纪律），每个提交精确点名文件。
- 每个任务收尾必须过：`go build ./...`、`go test ./...`（涉包）；批次收尾过 `make lint`、`make eval`、`make e2e`。
